手机里没有“拖文件”这回事（触摸屏触发不了拖拽事件）——点橙色按钮看投篮，或用「选择文件」。
这段交互好在哪（一句话）

它把两种输入塞进同一个落区：能拖就拖，不能拖就拍一张，第二选择当场给出，不用另开按钮位； 然后用右上角计数徽章做最小反馈——不弹 toast，也知道东西收进去了。

整个视频只有 5.5 秒、一句话没说，全靠落区变脸 + 数字跳动把话说完了。

核心：四个拖拽事件

dragover 不 preventDefault，drop 永远不会触发

这是新手第一个坑：浏览器默认把拖进来的文件当"导航"，你不喊停，它就跳走了。

const drop = document.getElementById('drop');

drop.addEventListener('dragover', e => {
  e.preventDefault();                       // 必须：允许放下
  e.dataTransfer.dropEffect = 'copy';     // 光标显示"复制"
});

drop.addEventListener('drop', e => {
  e.preventDefault();
  addFiles(e.dataTransfer.files);           // 这里才是真文件
});

另外把整页的默认行为也堵住，否则文件没拖准、掉在框外，浏览器直接打开那个文件，页面就没了：

['dragover', 'drop'].forEach(t =>
  window.addEventListener(t, e => e.preventDefault()));
第二个坑：高亮会闪

dragenter / dragleave 会从子元素冒泡上来

落区里只要有图标和文字，鼠标从文字移到图标就会触发一次 leave + enter。 直接用布尔值开关，边框就会疯狂闪。正解是计数：进一个加一，出一个减一，减到 0 才取消高亮。

let depth = 0;

drop.addEventListener('dragenter', e => {
  e.preventDefault();
  depth++;
  drop.classList.add('over');
});

drop.addEventListener('dragleave', () => {
  depth--;
  if (depth <= 0) { depth = 0; drop.classList.remove('over'); }
});

高亮本身也不用换一整块背景，改边框色 + 轻微放大 1.012 + 一层淡蓝外发光就够了——观众感知到的是"它活过来了"，不是"颜色变了"。

"or take the shot" 怎么实现

拍照 = canvas 截一帧 → 变成 File → 走同一条路

关键设计是拍照不要单独做一套流程：截出来的图包成 File 对象，直接丢给同一个 addFiles()，后面的列表、计数、上传全都复用。

async function shoot() {
  const stream = await navigator.mediaDevices.getUserMedia({
    video: { facingMode: 'environment' }      // 手机优先后置
  });
  video.srcObject = stream;
  await video.play();

  const c = document.createElement('canvas');
  c.width = video.videoWidth; c.height = video.videoHeight;
  c.getContext('2d').drawImage(video, 0, 0);

  const blob = await new Promise(r => c.toBlob(r, 'image/jpeg', 0.9));
  addFiles([new File([blob], `scan_${Date.now()}.jpg`, { type: 'image/jpeg' })]);

  stream.getTracks().forEach(t => t.stop());   // 用完必须关，不然摄像头灯常亮
}

getUserMedia 只在 https 或 localhost 下可用。本地双击打开（file://）会直接失败——所以下面那句降级提示是必需的，不是客套。

让"收下了"这件事被看见
① 计数徽章0→1 有个 1.24 倍的 pop，再变实心蓝。比 toast 便宜，比静默强。
② 新行入场文件卡片从下方 6px 淡入上浮，200ms 过阻尼——"东西落进去了"。
③ 状态就地变上传中用 3px 进度条，完了变绿字"已上传"，不弹窗。
④ 落区变脸拖拽悬停时文案尾巴追加"松手就收下"，把下一步说清楚。

这四个都是零成本反馈：不占布局、不需要新组件、不打断用户。做工具和做作品集都值这几行。

"take the shot" 是双关

这句话两层意思叠在一起：拍一张（camera）和投一球（basketball）。 落区上面画的是一个橙色篮筐，所以把文件拖进去这件事，被做成了"把文件投进筐里"。

这就是我说"这个交互有点意思"的真正原因——不是动效花，是它把一句功能文案玩成了梗， 而且玩梗不耽误用：文案本身把两种输入都说清楚了。

Demo 里这段投篮是怎么做的

抛物线不用物理引擎，三个关键帧就够

真拖拽没法让代码自动播给别人看（事件得用户触发），手机微信里更没有拖拽事件。所以演示用一个假球： 算出球在面板里的起点、篮圈的位置、再加一个"最高点"，用 Web Animations 串成三段，边飞边转。

const pr = panel.getBoundingClientRect();     // 面板坐标
const hr = hoop.getBoundingClientRect();      // 篮筐坐标

const sx = pr.width * .10, sy = pr.height - 56;      // 起点：左下角
const ex = hr.left - pr.left + hr.width/2 - 17;       // 终点：篮圈中心
const ey = hr.top  - pr.top  + hr.height * .42 - 17;
const mx = (sx + ex) / 2, my = Math.min(sy, ey) - 92; // 最高点抬高 92px

ball.animate([
  { transform: `translate(${sx}px,${sy}px) rotate(0deg)`,    offset: 0   },
  { transform: `translate(${mx}px,${my}px) rotate(-200deg)`, offset: .55 },
  { transform: `translate(${ex}px,${ey}px) rotate(-390deg)`, offset: 1   }
], { duration: 900, easing: 'linear', fill: 'forwards' });

为什么用 linear 而不是 ease-out：抛物线在水平方向是匀速的，减速感应该来自重力，不是缓动曲线。 想更像真球，可以把 duration 拆成两段（上升 420ms / 下落 480ms），下落那段用 cubic-bezier(.4,0,1,.6) 加速。

进筐那一下：篮网砸下去再回弹

球的动画结束后，给篮网加一个 class，让它纵向压到 0.74 再回弹到 1.08（过阻尼），篮圈同时闪一下绿色。 这就是"进了"的全部反馈——没有音效、没有粒子，两个动作而已。

.hoop .net{ transform-box:fill-box; transform-origin:50% 0% }
.hoop .net.swish{ animation:netSwish 460ms cubic-bezier(.3,1.4,.5,1) }
@keyframes netSwish{
  26% { transform:scaleY(.74) translateY(4px) }   /* 被砸下去 */
  58% { transform:scaleY(1.08) translateY(-1px) } /* 回弹过头 */
}

两个坑：① SVG 元素的 transform-origin 必须配 transform-box:fill-box，否则会绕着 SVG 左上角变形； ② 动画类用完要移除（classList.remove），不然第二次点不会重播。

取舍：这种自动播放适合演示/录屏/作品集，别塞进真实产品——用户会以为界面自己在动。 真实产品只保留 hover 反馈和进筐后的计数变化。
视频里能确认的 / 我没能确认的

能确认（逐帧 OCR + 像素取证）：落区文案是 Drop files here / or take the shot；落区里有一块 62×34 的橙色描边图形，把这块裁下来单独给视觉模型看，答"Basketball hoop"——所以是篮筐，不是相机图标； 右上计数从 0 跳到 1；落地后出现一行 final_final_v7.pdf · 2.4 MB，状态 Uploaded。

没能确认：原视频里那个"球"到底是文件卡还是篮球、抛的是几段弧、篮网有没有回弹。 5.5 秒的视频里这层信息我靠差分和亮度推不出来，所以本页的投篮是按这句话的双关做的复刻，不是逐帧还原。
