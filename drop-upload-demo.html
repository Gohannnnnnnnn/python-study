核心：四个拖拽事件

dragover 不 preventDefault，drop 永远不会触发

这是新手第一个坑：浏览器默认把拖进来的文件当"导航"，你不喊停，它就跳走了。

const drop = document.getElementById('drop');

drop.addEventListener('dragover', e => {
  e.preventDefault();                       // 必须：允许放下
  e.dataTransfer.dropEffect = 'copy';     // 光标显示"复制"
});

drop.addEventListener('drop', e => {
  e.preventDefault();
  addFiles(e.dataTransfer.files);           // 这里才是真文件
});

另外把整页的默认行为也堵住，否则文件没拖准、掉在框外，浏览器直接打开那个文件，页面就没了：

['dragover', 'drop'].forEach(t =>
  window.addEventListener(t, e => e.preventDefault()));
第二个坑：高亮会闪

dragenter / dragleave 会从子元素冒泡上来

落区里只要有图标和文字，鼠标从文字移到图标就会触发一次 leave + enter。 直接用布尔值开关，边框就会疯狂闪。正解是计数：进一个加一，出一个减一，减到 0 才取消高亮。

let depth = 0;

drop.addEventListener('dragenter', e => {
  e.preventDefault();
  depth++;
  drop.classList.add('over');
});

drop.addEventListener('dragleave', () => {
  depth--;
  if (depth <= 0) { depth = 0; drop.classList.remove('over'); }
});

高亮本身也不用换一整块背景，改边框色 + 轻微放大 1.012 + 一层淡蓝外发光就够了——观众感知到的是"它活过来了"，不是"颜色变了"。

"or take the shot" 怎么实现

拍照 = canvas 截一帧 → 变成 File → 走同一条路

关键设计是拍照不要单独做一套流程：截出来的图包成 File 对象，直接丢给同一个 addFiles()，后面的列表、计数、上传全都复用。

async function shoot() {
  const stream = await navigator.mediaDevices.getUserMedia({
    video: { facingMode: 'environment' }      // 手机优先后置
  });
  video.srcObject = stream;
  await video.play();

  const c = document.createElement('canvas');
  c.width = video.videoWidth; c.height = video.videoHeight;
  c.getContext('2d').drawImage(video, 0, 0);

  const blob = await new Promise(r => c.toBlob(r, 'image/jpeg', 0.9));
  addFiles([new File([blob], `scan_${Date.now()}.jpg`, { type: 'image/jpeg' })]);

  stream.getTracks().forEach(t => t.stop());   // 用完必须关，不然摄像头灯常亮
}

getUserMedia 只在 https 或 localhost 下可用。本地双击打开（file://）会直接失败——所以下面那句降级提示是必需的，不是客套。

让"收下了"这件事被看见
① 计数徽章0→1 有个 1.24 倍的 pop，再变实心蓝。比 toast 便宜，比静默强。
② 新行入场文件卡片从下方 6px 淡入上浮，200ms 过阻尼——"东西落进去了"。
③ 状态就地变上传中用 3px 进度条，完了变绿字"已上传"，不弹窗。
④ 落区变脸拖拽悬停时文案尾巴追加"松手就收下"，把下一步说清楚。

这四个都是零成本反馈：不占布局、不需要新组件、不打断用户。做工具和做作品集都值这几行。

Demo 为什么要自己演一遍

真拖拽没法自动播放，那就造一个假拖拽

浏览器的事件是用户触发的，代码没法"模拟一次真拖"给观众看；手机微信里更是没有拖拽事件。 所以演示用一张假文件卡 + 假光标，用 transform 从角落飞到落区中心，中途手动加上和真拖拽同一个 .over class—— 看起来就是拖进去的过程，实现却只有三行定位计算。

const pr = panel.getBoundingClientRect();      // 面板坐标
const zr = drop.getBoundingClientRect();       // 落区坐标

ghost.style.transform =
  `translate(${zr.left - pr.left + zr.width*.4}px,
               ${zr.top  - pr.top  + zr.height*.3}px)`;

await sleep(520); drop.classList.add('over');   // 飞到附近 → 落区变脸
await sleep(300); addFiles([file]);              // 收下 → 计数 +1

两个要点：① 设起点后要 void ghost.offsetWidth 强制重排，否则起点和终点会一起生效、看不到位移； ② 动画里加的那个 .over 必须和真拖拽时加的是同一个 class，不然演示和实物会不一致。

取舍：这种自动播放适合做演示/录屏/作品集，别塞进真实产品里——用户会以为界面在自己动。 真实产品只保留 hover 反馈。
