UI 组件速查

说准名字，AI 才写得对 · 9 种浮层 + 选型标准 + 3 个坑
一句话记住："弹窗"是所有浮层的统称。你说"加个弹窗"，AI 只能猜；说"弹个 Toast"，它立刻知道要一闪而过、不打断操作。
（内容整理自 Ludi 的抖音视频，2026-10-19；按截图与画面文字还原）
一、认得名字（7 种常用浮层）
Toast轻提示非模态
一闪而过（2-3 秒自动消失），不挡操作。
用在：保存成功、复制成功、请求失败
话术：「保存成功后弹个 Toast，自动消失」
Tooltip文字提示非模态
悬停（手机上长按）出现的一小段文字，只解释、不能点。
用在：图标含义、字段说明
话术：「这个问号图标加个 Tooltip 说明规则」
Alert警告条非模态
嵌在页面里的横幅，一直待着，直到条件消失或用户关掉。
用在：表单顶部错误汇总、系统维护通知
话术：「页面顶部放个 Alert 提示报名截止」
Popconfirm气泡确认打扰最小
就在按钮旁边弹个小气泡问一句"确定删除吗？"——鼠标不用挪窝。
用在：删除单条记录、取消订单
话术：「删除按钮加 Popconfirm 二次确认」
Modal / Dialog模态弹窗模态
居中弹出 + 遮罩，挡住页面，必须处理完才能继续。
用在：登录、新建表单、支付、重要确认
话术：「点新增用 Modal 弹一个表单」
最重的一种。能不用就别用。
Drawer抽屉半模态
从侧边滑出的面板，背后的列表还在，焦点不丢。
用在：编辑详情、筛选、设置、移动端导航
话术：「点这一行，用 Drawer 从右边滑出编辑面板」
Popover气泡卡片补充
点一下弹出的浮层，里面可以放按钮、链接、小表单。
用在：头像菜单、快捷操作
话术：「点头像弹 Popover，放"设置/退出"」

三、内容一多，选弹窗还是抽屉还是新页面？
判断法① 看内容长短（以 1440px 屏幕为基准）
表单宽度大致分 400 / 520 / 720 三档；超长表单一律出局——改用 Drawer 抽屉或新页面。
判断法② 要不要左右对照
需要一边看列表一边改内容 → Drawer（背后列表还在，焦点不丢）。
不需要对照、就是要用户专心做完一件事 → Modal。
情况选
内容很少，问一句就行Popconfirm
中等表单、要用户专注完成Modal
超长表单 / 要边看列表边改Drawer
内容极多、要独立浏览新页面
四、3 个坑（视频说 90% 的人都踩过）
坑 ①
填表的弹窗，别"点蒙层就关"
用户填了一半，手一滑点到旁边——数据全没。
正确做法：填表弹窗要么禁止点蒙层关闭，要么加草稿自动保存。
话术：「这个表单弹窗别点蒙层关，另加草稿自动保存」
坑 ②
能撤销，就别二次确认
删了能找回 → 直接删，给一个"撤销"条（撤销比确认省事，还少一次点击）。
删了找不回 → 才弹窗拦一下。
话术：「删除后给个撤销 Toast，不要弹确认框」
坑 ③
按钮别写"是 / 否"
用户在弹窗上的注意力只有 0.2-0.3 秒（视频标注 299ms）。写"是/否"他得回头看问题。
正确做法：按钮直接写动作——"确认退票"而不是"是"，并把后果写在旁边（如"将扣除 30 元手续费"）。
话术：「按钮文字写具体动作，别用是/否」
五、最容易混的四组
Toast vs AlertToast 一闪而过；Alert 嵌在页面里常驻。
Tooltip vs PopoverTooltip 只能看文字；Popover 能点能放按钮。
Modal vs DrawerModal 居中挡住整页；Drawer 侧滑、背后列表还在。
Popconfirm vs ModalPopconfirm 就在按钮旁边问一句；Modal 是整页级的大事。
