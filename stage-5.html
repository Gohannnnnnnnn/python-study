第 23 课 · py-023

读写文件：把数据存进硬盘

知识要点

1. open 三种模式——r / w / a
f = open("记录.txt", "r")   # r=读，文件必须存在
f = open("记录.txt", "w")   # w=覆盖写，原有内容全没
f = open("记录.txt", "a")   # a=追加写，保留原有，从末尾加
医生类比：r = 翻病历看；w = 撕掉重写一页；a = 翻开最后一页继续记。a 是「打开模式」不是方法——append 是列表的方法，别混。
2. 读文件三步 + 逐行读
f = open("记录.txt", "r", encoding="utf-8")
内容 = f.read()          # 一次性全读进来
f.close()

# 大文件逐行读（省内存）：
f = open("记录.txt", "r", encoding="utf-8")
for 行 in f:            # 一行一行取
    print(行.strip())
f.close()
3. ⚠️ encoding 必须写 + 不 close 的后果

中文文件必须写 encoding="utf-8"，否则 Windows 默认按 gbk 读 → 乱码。

不 close() → ① 数据还在缓冲区没落盘；② 文件被占用别人打不开。

一句话总结：r 读、w 覆盖、a 追加；读文件 open → read/for 行 → close；中文必须 encoding="utf-8"；忘 close 数据不落盘还占着文件。

第 24 课 · py-024

with 语句 + JSON 读写

知识要点

1. with 语句——自动关门
# 以前：手动关，忘写 f.close() 就出事
f = open("记录.txt", "a", encoding="utf-8")
f.write("张三 36.8\n")
f.close()

# 现在：with 自动关
with open("记录.txt", "a", encoding="utf-8") as f:
    f.write("张三 36.8\n")
# 缩进一结束，Python 自动 close
医生类比：with = 进病房门设成「自动关」，缩进里做事，离开自动锁门——再也不用记 f.close()。
2. json.dump 存 / json.load 读——类型不变
import json

病人 = {"姓名": "王五", "体温": 39.0}
with open("病人.json", "w", encoding="utf-8") as f:
    json.dump(病人, f, ensure_ascii=False)   # 存

with open("病人.json", "r", encoding="utf-8") as f:
    读回 = json.load(f)                        # 读
print(读回["体温"])   # 39.0
方向别记反：dump = 倒进去存，load = 装出来读。存的是字典，读回来还是字典（类型不变）。
3. ⚠️ 存多个记录用「列表套字典」
# 一个字典装不下两个病人（一个键一个值）——外层要用列表
病人 = [
    {"姓名": "王五", "体温": 39.0},
    {"姓名": "赵大", "体温": 38.8}
]
with open("病人.json", "w", encoding="utf-8") as f:
    json.dump(病人, f, ensure_ascii=False)

# 读回来是列表，取值要剥两层：
读回 = json.load(open("病人.json", "r", encoding="utf-8"))
print(读回[0]["姓名"])   # 王五（先 [0] 取第几个，再 ["姓名"] 取字段）
ensure_ascii=False：中文原样存，不转成 \u 乱码。
一句话总结：with 自动关门省心；json.dump 存、json.load 读、类型不变；存多个记录用列表套字典；方法调用永远用 () 不是 {}。

参考答案

第 25 课 · py-025

CSV 读写：表格数据

知识要点

1. CSV 是什么——纯文本的表格
date,item,amount
09-08,coffee,18
09-09,bus,4
09-10,book,59
格式：一行一条记录，逗号分列，第一行是表头。本质是纯文本，记事本和 Excel 都能打开——这就是它几十年不死的原因。
三种文件格式的分工：txt 存流水文本 / csv 存表格 / json 存嵌套结构。
2. 写 CSV：csv.writer + writerow
import csv

rows = [
    ["date", "item", "amount"],   # 一行 = 一个列表
    ["09-08", "coffee", 18],
]
with open("expenses.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    for row in rows:
        writer.writerow(row)      # 写一行
⚠️ newline="" 是 Windows 上的规矩：不加它，每写一行会多插一个空行，文件变成隔一行空一行。
3. 读 CSV 的两种读法
# A. csv.reader：每行给你一个列表
with open("expenses.csv", "r", encoding="utf-8") as f:
    for row in csv.reader(f):
        print(row)          # ['09-08', 'coffee', '18']

# B. csv.DictReader：每行给你一个字典，表头当键（更常用）
with open("expenses.csv", "r", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        print(row)          # {'date': '09-08', 'item': 'coffee', 'amount': '18'}
DictReader 的心智：row 是字典，row["amount"] 是从字典里掏出的一格值——问类型要问「最后手上拿到的那个东西」。
4. ⚠️ 最大的坑：读出来的一切都是字符串
amount = float(row["amount"])   # '18' → 18.0，算钱必须自己转

写进去的是数字 18，读回来是字符串 '18'——跟 input() 返回字符串一模一样的毛病：从文件/键盘进来的东西，Python 一律当文本。

5. ⚠️ 累加必须在同一个循环里
total = 0.0                          # 进循环之前先让它存在
for row in reader:
    amount = float(row["amount"])
    total = total + amount            # ✅ 累加：攒住
    # total = float(row["amount"])    # ❌ 覆盖：循环结束只剩最后一个值
循环里的赋值 = 把上次的扔掉换成这个。想攒东西只能累加；而累加的那个变量必须在进循环之前就存在。
一句话总结：CSV 是逗号分隔的纯文本表格；写用 csv.writer + writerow（Windows 必须加 newline=""），读用 DictReader（表头当键）；读出来全是字符串要 float() 转；累加变量放循环外、用「自己 = 自己 + 新值」攒。

A. 分号和空格　　B. 换行和逗号　　C. 逗号和换行　　D. 制表符和分号

参考答案
B。一行一条记录（靠换行分），一条记录里的列靠逗号分。

A. 直接报错　　B. 中文乱码　　C. 每行之间多出一个空行　　D. 文件打不开

参考答案
C。文件变成「隔一行空一行」。newline="" 专治这个毛病。

基础类型

用 DictReader 读，row["amount"] 拿到的类型是？

A. int　　B. str　　C. float　　D. dict

参考答案
B。CSV 读出来的一切都是字符串，要算数得自己 float()。注意 row 本身是 dict，但 row["amount"] 是掏出来的那一格值。
4
进阶累加

for row in reader: 里只写 total = float(row["amount"])，循环结束后 total 是什么？

A. 所有金额之和　　B. 0　　C. 只剩最后一行的金额　　D. 报错

参考答案
C。每一轮都把上一轮的值覆盖掉，循环结束只剩最后一个。要攒住必须写成 total = total + float(...)。
5
进阶报错排查

在 for row in reader: 里又套一层 for n in num:（num 是 float(row["amount"])），报 TypeError: 'float' object is not iterable。该怎么改？

A. 把 num 转成列表　　B. 删掉这层 for，直接 total = total + num　　C. 把 num 转成字符串　　D. 换成 while 循环

参考答案
B。报错的意思是「这个动作对这类对象不成立」——外层 for 已经在逐行了，num 就是这一行的金额（一个数），不需要也不能再遍历。删掉这层循环就对了。
第 26 课 · py-026

try / except：让程序出错不崩

知识要点

1. 不处理异常 = 程序当场死亡

跑到某一行干不了（文件不在、除以 0、键不存在、类型不对），Python 当场停在那行，后面的代码一行都不跑。

注意准确含义：不是「报个错然后继续跑」，是「整个程序死掉」——后面那句话永远不会被打印。

2. try / except = 安全网
try:
    num = int(input("请输入一个数字："))   # 「我试试干这件事」
    print("你输入的是", num)
except ValueError:                       # 「要是炸了，改走这条路」
    print("这不是数字，请重新输入")

输入 abc → int() 干不了 → 本来要当场死 → 有网接住 → 打印友好提示 → 程序继续往下正常跑。
ValueError = 「值的类型不对」：int() 想要数字样子的字符串，你给了 abc。

3. ⚠️ except 类型写错 = 接不住（本课最容易翻车处）
try:
    with open("不存在.txt", "r", encoding="utf-8") as f:
        data = f.read()
except ValueError:            # ❌ 抓不到 FileNotFoundError
    print("出错了")
print("程序结束")             # ← 这行根本不会执行

实测结果：照样崩，报 FileNotFoundError: [Errno 2] No such file or directory，print("程序结束") 没打印。

except 只接住你点名的那个类型，其他一律放行。这不是缺陷，是「精准捕获」——免得真正的 bug 被你的友好提示藏起来。

4. 读报错（Traceback）的方法

从最后一行往上读：最后一行 = 什么错（FileNotFoundError），往上一行 = 错在哪（哪一行干了什么）。中间那堆「谁调用了谁」的层级，新手先忽略。

一句话总结：try 里放「可能出事的动作」，except 里写「出事后走哪条路」；except 后面必须点准异常类型，点错等于没写；读报错从最后一行往上读。

练习题

1
基础try 的作用

try 块里该放什么代码？

A. 一定不会出错的代码　　B. 可能出错的代码　　C. 出错后要执行的代码　　D. 函数定义

参考答案
B。try 包住「可能出事的动作」，出事后的处理写在 except 里。

int("abc") 会抛出哪种异常？

A. FileNotFoundError　　B. ZeroDivisionError　　C. ValueError　　D. KeyError

参考答案
C。值的形式不对 → ValueError。ZeroDivisionError 是除以 0，KeyError 是字典里没这个键。

参考答案
B。try 和 except 是配对出现的：缩进 + 冒号都要写，except 后面点明异常类型。

进阶接不住

A. 打印 except 里的提示，程序继续　　B. 照样崩，except 后面的代码都不执行　　C. 自动重试　　D. 打印空行

参考答案

5
进阶实用场景

写一个「读 CSV 算总计」的脚本，要保证 CSV 不存在时给出友好提示而不崩，应该把什么放进 try 里？

A. 只放 open(...) 那一行　　B. 整个「打开 + 读取 + 循环 + 累加」段落　　C. 只放最后的 print　　D. 整个程序
